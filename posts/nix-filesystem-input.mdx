## Purely functional package management

One of the most difficult things to understand when starting to learn Nix is
what it really means for Nix to be a functional programming language. Many
Computer Science graduates and Software Engineers are aware of the idea of
functional programming, but understanding this idea as applied to package
management and operating systems is non-obvious at best.

Nix aspires to be a [purely functional package manager](https://nixos.org/guides/how-nix-works/).
This means that derivations, the functional unit of Nix, should be reproducible
in so far as the same inputs to a function should always give the same outputs.

Nixpkgs, the package set built with Nix and used by NixOS and friends, is by
definition just a [program](https://blog.obsidian.systems/compiler-bootstrapping-in-nixpkgs/).
Given an input, usually a package that we want to build, Nix evaluates a set of
pure functions that will always return the same output. While some of these
functions are just helpful abstractions like we would create in any other
language, other functions create derivations that we can then build.
